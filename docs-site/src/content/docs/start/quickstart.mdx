Extraction is asynchronous. `POST /v1/extract` returns `202` with one or more job IDs, and the text is available after a worker finishes. Poll `GET /v1/jobs/{id}`, or let Xberg call you with a [webhook](/guides/webhooks/).

You need a running instance ([Docker](/start/pro-docker/), [Pro on Helm](/start/pro-helm/) or [Enterprise](/start/enterprise-helm/)), its base URL and a project API key. Pro and Enterprise serve the same extraction routes, so moving between them changes the base URL and key, not the code.

## Extract one file

Set the base URL and key, then submit a file:

<Tabs syncKey="lang">
<TabItem label="curl">

```bash title="curl"
export XBERG_URL=http://localhost:8080
export XBERG_API_KEY=kz_your_key_here

# /v1/extract answers 202 with { "job_ids": [...], "status": "pending" }.
JOB=$(curl -sX POST "$XBERG_URL/v1/extract" \
  -H "Authorization: Bearer $XBERG_API_KEY" \
  -F "file=@invoice.pdf" | jq -r '.job_ids[0]')

# Poll until the job reaches a terminal status, then print the text.
while true; do
  STATUS=$(curl -s "$XBERG_URL/v1/jobs/$JOB" \
    -H "Authorization: Bearer $XBERG_API_KEY" | jq -r .status)
  case "$STATUS" in completed|partial_success|failed|cancelled) break ;; esac
  sleep 1
done
curl -s "$XBERG_URL/v1/jobs/$JOB" \
  -H "Authorization: Bearer $XBERG_API_KEY" | jq -r .result.content
```

</TabItem>
<TabItem label="Python">

```python title="Python"
import asyncio
import os
from pathlib import Path
from xberg_io_sdk import AsyncXbergClient

async def main() -> None:
    async with AsyncXbergClient(
        base_url=os.environ["XBERG_URL"],
        api_key=os.environ["XBERG_API_KEY"],
    ) as client:
        job = await client.extract_and_wait(file=Path("invoice.pdf"))
        print(job.result.content)

asyncio.run(main())
```

<TabItem label="TypeScript">

```typescript title="TypeScript"
import { XbergClient } from "@xberg-io/sdk";
import { readFile } from "node:fs/promises";

const client = new XbergClient({
  baseUrl: process.env.XBERG_URL!,
  apiKey: process.env.XBERG_API_KEY!,
});
const data = await readFile("invoice.pdf");
const job = await client.extractAndWait({
  file: { name: "invoice.pdf", data, mimeType: "application/pdf" },
});
console.log(job.result?.content);
```

<TabItem label="Go">

```go title="Go"
package main

import (
    "context"
    "fmt"
    "log"
    "os"

    xberg "github.com/xberg-io/sdks/packages/go"
)

func main() {
    ctx := context.Background()
    client, err := xberg.New(
        xberg.WithBaseURL(os.Getenv("XBERG_URL")),
        xberg.WithAPIKey(os.Getenv("XBERG_API_KEY")),
    )
    if err != nil {
        log.Fatal(err)
    }
    file, err := os.Open("invoice.pdf")
    if err != nil {
        log.Fatal(err)
    }
    defer file.Close()
    job, err := client.ExtractAndWait(
        ctx,
        xberg.FileSource{Name: "invoice.pdf", Reader: file},
        nil,
    )
    if err != nil {
        log.Fatal(err)
    }
    fmt.Println(job.Result.Content)
}
```

A single request accepts up to 10 documents inline, so submit several files in one call by repeating the `file` part (curl: `-F "file=@a.pdf" -F "file=@b.pdf"`). The response lists one job ID per file. For larger batches, use presigned uploads (`POST /v1/uploads/presign`, then `POST /v1/uploads/confirm`), which stage up to 100 documents.

## Job statuses

`GET /v1/jobs/{id}` returns one of seven `status` values. Treat `completed`, `partial_success`, `failed` and `cancelled` as terminal. Anything else means poll again.

| `status` | Meaning | `result` present |
|----------|---------|------------------|
| `awaiting_upload` | Job created, document upload not yet finalized | No |
| `pending` | Queued, not yet picked up | No |
| `processing` | A worker is extracting | No |
| `completed` | Done; the full result is available | Yes |
| `partial_success` | Some pages or files failed; a partial result is available | Yes |
| `failed` | Unrecoverable error; `error` carries the reason | No |
| `cancelled` | Job cancelled by the project | No |

The Python and TypeScript SDKs poll once per second, back off by a factor of two up to 30 seconds, and give up after five minutes. Tune this with `poll_interval` and `timeout` (`pollInterval` in TypeScript). Do not poll faster than once per second; rate limits apply.

<Aside>
Fetch the full result of a finished job from `GET /v1/jobs/{id}/result`. Use `GET /v1/jobs` to list recent jobs and crawl parents for the project.
</Aside>
